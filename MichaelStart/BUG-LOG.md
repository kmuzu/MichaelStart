## Quick Reference

### Priority Levels
| Priority | Meaning | Response Time |
|----------|---------|---------------|
| P1 - Critical | Game-breaking, crashes, data loss | Immediate |
| P2 - High | Major feature broken, significant impact | Soon |
| P3 - Medium | Minor feature issue, workaround exists | Normal |
| P4 - Low | Cosmetic, polish, nice-to-have | When time permits |

### Status Values
| Status | Meaning |
|--------|---------|
| Open | Identified, not yet worked on |
| In Progress | Currently being investigated/fixed |
| Testing | Fix implemented, needs verification |
| Resolved | Confirmed fixed |
| Won't Fix | Intentional behavior or not worth fixing |
| Deferred | Postponed to later |

## Tips for Effective Bug Reporting

1. **Be Specific:** Include exact steps, not just "it crashed"
2. **One Issue Per Entry:** Don't combine multiple bugs
3. **Include Context:** Version, what you were doing, recent changes
4. **Update Status:** Keep the log current as you work
5. **Document Solutions:** Future-you will thank present-you
